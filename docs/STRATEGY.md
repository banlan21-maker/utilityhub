## 1. 장기 방향 (구상)

**"현장 실무자를 위한 도구 모음"으로 무게중심을 옮긴다.**

- 사무실용 범용 툴(부가세, 퍼센트, QR 등)은 이미 대형 사이트·구글 자체 계산기가 장악했고, 이제 일반인도 AI로 쉽게 만들 수 있다.
- AI 시대에 블루칼라 직종 수요와 **초보 인력**이 늘어날 것으로 본다. 초보는 현장에서 계산·판단·작업 순서에서 막힌다.
- 대상 직종 예시: 전기공사, 인테리어, 목수, 페인트, 도배, 타일, 설비/배관, 헤어디자이너 등.
- 경쟁력: 현장 경험이 들어간 툴은 남들이 쉽게 못 만든다(정확한 공식 + 도면 + 실수하기 쉬운 부분 안내).

> ⚠️ 이 방향은 **가설**이다. 아래 측정·검증 결과를 보고 확정한다. 전면 리브랜딩은 하지 않는다.

## 3. 확인된 사실 vs 가설

### 확인된 사실
- 등록 툴 87개 (`src/lib/tools-registry.ts`, meeting-burner 등록 누락분 추가 후). sitemap URL 206개.
- Search Console(2026-10-23): 색인 39 / 미색인 191 — 발견됨-미색인 134, 크롤링됨-미색인 35, 리디렉션 14, 404 4, 다른 표준 선택 3, 대체 페이지 1.
- **툴 상세 페이지 87개 × ko/en = 174페이지 전부** raw HTML에 h1 1개·본문·FAQ·JSON-LD 존재 (로컬 빌드 curl 전수 검사, 2026-10-23).
  → `'use client'` 컴포넌트도 서버에서 HTML로 렌더된다. SEO 텍스트를 page.tsx로 옮길 필요는 없고, 문제는 `mounted`/`isClient` 가드 같은 SSR 중단 패턴뿐이다.
- **색인 정체의 유력 원인(확인·수정·배포 완료):** 홈은 카테고리 링크만, 카테고리 페이지 10개는 `if (!isClient) return null`로 서버 HTML이 비어 있어 **툴 페이지로 가는 내부 링크가 raw HTML에 0개**였다(고아 페이지). 카테고리 title도 10개 모두 동일.
- 현재(배포 후): 홈 ko/en 툴 링크 87개, 카테고리별 고유 title·소개 문단·툴 링크, 툴 페이지 관련 도구 최대 6개, ko 홈 canonical `/ko`, 전 페이지 hreflang x-default.
- cable-tray-calc raw HTML: h1 1개, 본문 en 751단어 / ko 595단어, FAQ JSON-LD 존재, noindex 없음.
- 분석 도구: Vercel Analytics(페이지뷰)만 있음. 계산·복사·공유 이벤트 측정 없음.
- "데이터를 수집하지 않습니다"류 문구가 messages/ko·en.json, privacy 페이지에 약 25곳 존재.
- 남은 공통 결함: 툴 대부분의 **EN 페이지 JSON-LD가 한국어**(url도 /ko 고정) — salary-calc만 수정됨. `/en/.../excel-mapper`는 `SmartExcelMapper` 영문 번역 네임스페이스 누락.

### 가설 (검증 필요)
- 범용 툴은 경쟁이 심해 검색 유입이 적을 것이다.
- 현장 계산기는 검색량은 적지만 경쟁도 적고 재사용률이 높을 것이다.
- 주제가 섞인 구성은 실무 사용자 신뢰에 불리할 수 있다(검색 순위 영향은 미확인).
- "발견됨-미색인 134"는 내부 링크 부재가 주원인일 것이다 → 수정 배포(2026-10-23) 후 4~6주 내 감소 여부로 검증.
- "크롤링됨-미색인 35"는 콘텐츠 품질·EN 페이지 언어 불일치 영향일 수 있다(미검증).

## 4. 실행 계획

### ① 사용 측정 (최우선)
개선 작업 **전에** 넣어야 전후 비교가 가능하다.

| 이벤트 | 기준 |
|---|---|
| 계산 성공 | 유효한 입력으로 결과가 생성됨. 자동 계산 툴은 입력이 멈춘 뒤 확정된 결과만, **페이지 방문 1회당 1번** 집계 |
| 결과 복사 | 클립보드 복사가 실제로 성공했을 때만 |
| 공유 | 버튼 클릭과 실제 완료를 구분, 확인 가능한 범위만 |
| 입력 오류 | 어느 항목에서 막히는지만. **입력값 자체는 수집하지 않음** |

- 입력값·계산 결과 원문은 수집하지 않는다.
- 초기 지표: 툴별 **방문 대비 계산 성공률, 복사율**. 재방문은 별도 정의.
- 도구 선택: GA4(무료) vs Vercel 커스텀 이벤트(유료 플랜) — 비용 비교 후 결정.
- 도입 시 개인정보 문구 약 25곳을 실제 동작에 맞게 수정("익명 사용 통계 수집" 명시).

### ② 현장 계산기 3개 집중 개선
대상: **케이블 트레이 / 전선 굵기 / 배관·엘보 오프셋**

개선 축:
- 정확성: 계산식·단위·적용 조건·기준 출처 명시. **사용자 현장 검증 항목**과 **공식 규격·자동 테스트 항목**을 구분.
- 이해도: 실제 현장 입력 예제, 계산 과정, 도면.
- 모바일: 현장에서 한 손 입력, 큰 글씨, 결과 공유.
- 기술 수정과 기능 개선은 아래 변경 기록에 **각각** 남긴다.

케이블 트레이 우선 과제(2026-10-23 검토):
- 도면: V-컷 깊이가 실제와 불일치(55%만 그림), 축척 왜곡, 마킹 간격 A 미표시, 라벨 겹침·작은 글씨
- 타공 ±70mm가 V-컷 영역 안에 찍히는 경우 있음 → **현장 기준 확인 필요**
- 개선안: 3D 형상(접기 애니메이션) + 마킹용 전개도 병행 검토
- 색상 CSS 변수화, EN JSON-LD 영문화
- ~~SEO 콘텐츠를 page.tsx(서버)로 이동~~ → 불필요(raw HTML에 이미 포함됨, 위 "확인된 사실" 참고)
- 관련 도구 toolId 오류(cable-tray, wire-size)는 2026-10-23 수정 완료

### ③ 직종 불편함 조사 (병행)
- **전기 시공부터** 시작. 실제 사례(지식iN, 커뮤니티, Reddit 등)를 모아 반복되는 문제를 추린다.
- 분류: 계산형 / 판단형(→ 툴 후보) · 지식형(→ 가이드) · 기술형(→ 툴 대상 아님)
- 실무자 인터뷰 질문:
  1. 최근 현장에서 직접 계산하거나 엑셀·종이로 처리한 일이 무엇인가요?
  2. 이 계산기를 실제 작업에 쓰려면 무엇이 부족한가요?
  3. 결과를 누구에게 어떤 형태로 전달해야 하나요?
